# ttf.q38: Qwen3.8-Flash-Next in TTF

Qwen3.8-Flash-Next (HF `model_type` qwen4_exp: 48 layers of gated DeltaNet / gated attention with 4 gated residual
streams, 512 routed experts + a shared expert per layer, a hashed 2/3-gram PLE embedding) converted to ternary
weights and trained further with TTF, one layer at a time on one GPU, with the model and the TTF state in host memory.
Needs transformers >= 5.19 (its Qwen3.5-MoE parts; `ttf.q38.model` writes the qwen4_exp-only pieces).

## Modules

| Module | What it holds |
|---|---|
| `ttf.q38.model` | the text decoder (gated residual, PLE, MoE, QSA as dense causal attention for T <= 2048), the FP8 reader, per-layer loading |
| `ttf.q38.moe` | `TernaryExperts` / `TernLinear` (trits packed 5 per byte, row / column scales, centring, ternary low-rank adapter) and their TTF update batched over experts (`ExpertTTF`, the core's one-batch factored rule; `AdapterTTF`) |
| `ttf.q38.moe_gg` | Triton grouped GEMMs over expert segments (int8 exact and bf16), the batched fire, fused norms / conv / combine |
| `ttf.q38.train` | the layer-major trainer: forward with the layer inputs stashed on the host, KD head (top 64 + 64 sampled tail), per-layer recompute + backward, per-layer TTF updates, AdamW fp32 masters, per-layer checkpoints, slim saves |
| `ttf.q38.store` | the FP8 release read once into host memory (experts as stacked FP8 bytes), the PLE table as a memory map |
| `ttf.q38.ple_pq` | `PQTable`: the PLE table from its compressed store (prune + product quantization), decoded on the GPU |
| `ttf.q38.load` | `load_slim`: a trained student from a slim save, no Trainer (evaluation, analysis) |

The conversion and the teacher cache are in ttf-conversion (`ttfconv.q38.convert`, `ttfconv.q38.teacher`; checkpoint
tools and the PLE store build in its `scripts/q38`).

## Pipeline

```
# 1. slim base checkpoint (the language model without the routed experts) and the teacher's KD cache
python scripts/q38/hf_fetch.py SLIM                                  # (ttf-conversion) or slim.py from a full download
python -m ttfconv.q38.teacher HF_DIR DATA.bin KD --windows 16384    # top-64 + 64 sampled tail per position
# 2. conversion: every routed expert and dense projection to trits (ternary GPTQ, centred, ALS scales, rank-16
#    ternary adapters), layer by layer on one GPU
python -m ttfconv.q38.convert HF_DIR DATA.bin CONV --windows 256 --rank 16
# 3. optional: the compressed PLE table (prune1 + pq4.256, 7.95 GB instead of the 51.2 GB FP8 table)
python scripts/q38/ple_pq_build.py --model SLIM --data DATA.bin --data-u32 --out PQ
# 4. TTF training
python -m ttf.q38.train --model SLIM --conv CONV --kd-cache KD --data DATA.bin --data-u32 --out RUN \
    --steps 1000 --theta 50 --theta-end 140 --theta-rise-from 0.6 --tau 1000 --expert-theta-mult 1.25 \
    --ttf-start 20 --kd-weight 1 --ple-pq PQ --prefetch --expert-orth rchol --resident --wbatch 8 --compile-hc \
    --ttf-store bf16 --tf32 --save-every 100 --eval-every 50
# 5. evaluation of a slim save (ttf-core scripts/eval)
python scripts/eval/q38_gen_kv.py --model SLIM --slim RUN/slim_s1000 --bench BENCH --out OUT
```

The training recipe above (step 4) is the one of the 1k-step run: trits frozen for the first 20 steps (floats train),
θ 50 for dense projections and adapters, experts × 1.25, a cosine rise to θ 140 from 60% of the steps, the fixed leak
1 − 1/τ, all in rescale form (the bar stays fixed, `lr_ratio` scales by θ / θ(t), so a change of θ keeps the
evidence). At θ 16 this model's expert accumulators ran away within ~50 steps.

## Memory and speed (RTX PRO 6000, 96 GB)

One layer's weights and TTF state on the GPU at a time (`--resident` keeps the floats of all layers there). Host
memory: ~221 GB pinned (TTF state and stashed layer inputs), plus the model. `--ttf-store bf16` halves the host <-> device
traffic of U / V. A full checkpoint is ~3.3 GB per layer (149 GB with the optimizer state); a slim save (trits,
scales, adapters, floats) ~25 GB. Step time with the flags above: ~35 s per step of 16 windows of 2048 tokens.

## Tests

- `tests/test_q38_moe.py` (CPU + GPU): `TernaryExperts` forward / input gradient / factors against per-expert core
  `KernelTernaryLinear` layers; `ExpertTTF.update_b` against the core `_ts_layer_factored` per expert.
- `tests/test_q38_moe_gg.py` (GPU): the grouped GEMMs against a per-expert loop (int8 exact, bf16 to fp32 tolerance).
- `tests/checks/q38_model.py`, `tests/checks/q38_train.py` (CPU or GPU; in the CPU suite): a tiny random config end
  to end (PLE hashing, MoE against a dense loop, causality, layer-major gradients equal autograd, the loss falls with
  every kind of move, resume, SIGINT slim save).
- ttf-conversion `tests/checks/q38_pipeline.py` (GPU): store == in-memory model, teacher check and cache, a 3-layer
  conversion loading into `TernaryExperts`.
